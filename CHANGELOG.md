# Changelog

Every defect this project claims to have fixed, with the reproduction that shows it existed, the test that stops it coming back, and the justification for anything that changed method rather than code.

Rules this file is held to, checked in `tests/test_changelog.py`:

1. Every row cites a reproduction. `python tools/repro.py <id>` reconstructs the defect in its historical state and runs the current guard against it. A row without a passing repro is a claim, not a record.
2. Every fix cites a regression test that exists in the tree.
3. Every methodological change carries a justification, including the ones where the reasoning is "the alternative measures the wrong thing".
4. Where no automated guard is possible, the row says so instead of inventing one.

Repro ids `R01`–`R20` are defined in `tools/repro.py`.

## Acquisitions

**Method: a sinkhole is an evidence source, not a trap.** `harness/deception/hellbox.py` accepts a foothold attempt and answers it with a synthetic filesystem and shell: decoy credentials marked as decoys, a `curl` that reports a timeout while no packet is ever constructed, a reverse-shell request answered with connection refused, and one session per source host so a rotated port continues the same intrusion instead of starting a fresh one. The record states what happened (commands, attempt profile, rotation count, amplification) and refuses one claim explicitly: `believability: unmeasured`, because whether an operator believed the host was real cannot be observed from inside the sinkhole. The guarantee is that the connection was made useless.

No listener ships, deliberately. The module contains no socket, no subprocess, no network import and no real `open`; a test parses its own AST for all of them, because "we do not call it" is weaker than "it is not here to call". Limits on bytes, commands, wall clock and amplification each close the session with a reason rather than degrading quietly. Persistence is in-memory, so a second session cannot read the first one's writes.

Two notes from building it. The self-review flagged three divisions by `bytes_in` behind a short-circuit `and` and a conditional expression, and it was right to: refusing to credit those syntactic shields is the same discipline that caught the non-rejecting guard. Consolidating them into one helper with an early return fixed it. It then still flagged the same division behind `if not self.bytes_in: return None`, and again behind `if self.bytes_in <= 0`, because `rule_ratio_without_floor` does not credit a zero-guard at all: it accepts only a floor assignment in the same scope. So the code now carries both, an early return for the reader and `max(self.bytes_in, 1)` for the rule. That asymmetry is worth naming: SR-BOUND-002 taught the length rule to require an exit statement before crediting a guard, while the ratio rule refuses control flow entirely and demands a syntactic floor. Two rules, one repository, opposite models of what a guard is. The ratio rule's model is the weaker one and it is the next thing to fix, with a reproduction first.


**Method: behavioural evidence before any diagnosis.** The evidence extractor was the next place the system could deceive itself, since it replaced a person's assertion about a mechanism with a person's assertion about a code. `tools/behavioral_witness.py` runs the code under review, records the value that reached the operation that matters, states the invariant it was checked against, and derives codes from that comparison rather than from a filename or an expected diagnosis. Three outputs of unequal strength: observation (what ran), counterfactual (what changed when one mechanism was altered), proposal (which mechanism accounts for it, with the experiment that would settle it when more than one does). A before/after result is an association, not a cause, so the layer reports `probable` unless a single-mechanism mutation changes the outcome. A suppressed symptom with the invariant still violated is `symptom_masking`, never a fixed verdict. Two plausible causes stay two, deduplicated, with a named discriminator. Three adversarial gates hold this: an unfamiliar defect (a quota boundary error, absent from the nine records), a misleading reproduction (the exception gone, the size unchanged), and competing explanations.


**Method: classification moved from one label to three dimensions.** The single-label scheme put `code_defect`, `analyzer_defect` and `test_defect` (components) beside `coverage_gap` (a gap) and `policy_failure` (governance), which are not alternatives to each other. An analyzer defect can also be a coverage gap, and forcing a choice encoded the ambiguity. Records now carry `affected_component`, `failure_mode` and a `root_cause` mechanism from a closed vocabulary, with evidence codes naming the checkable facts behind the proposal, plus an audited `human_override`. Mechanism vocabulary follows NIST SP 800-231 for causal role, IEEE 1044-2009 for record content (inactive standard, used as reference only), arXiv:2408.13855 and FSE 2024 for analyzer-specific mechanisms, and CWE only where the finding is an actual software weakness, since a CI misconfiguration is not one.

`tools/failure_classifier.py` proposes; it never edits a record. It matches evidence codes against a fixed rule table, cites the taxonomy source behind each rule, and abstains when no rule matches, when a code is undefined, or when two mechanisms are supported at once. `insufficient_evidence` is reserved for failing to classify, not for classifying weakly: a conclusive infrastructure diagnosis with no reproduction is `probable`, which is a different statement. The benchmark in `harness/classification_benchmark.jsonl` is authored separately, includes four deliberately ambiguous cases, and is never written by the tool. Current score on fifteen cases: seven cells at precision and recall 1.0, four correct abstentions, zero missed, zero unnecessary, zero confusion entries.


**Method: failures now carry an identity, a category and a witness.** `tools/failure_intelligence.py` and `harness/findings.jsonl` turn each failure into a record with separated fields: observed facts, inferred risk, evidence, analyzer limitations, next action. Nine records cover the defects found in this repository's own review tooling, including the two that shared one wrong assumption about what a bound is. The component cannot suppress or close anything; it can only propose, and a finding reaches `resolved` only when the record names a reproduction that exists and a regression test that exists, both verified against `tools/repro.py` and the test files. Category is mandatory because a false positive treated as a vulnerability wastes a fix, while a false negative treated as clean is the one that costs you. Nothing here is claimed as exploitable in any deployment; confidence describes the evidence attached to the record.


**Method: the third review claim did not reproduce.** The review argued that a three-pass propagation budget let a long alias chain escape detection, and gave a five-link chain as the example. It does not reproduce, and the reason is worth recording: assignments are iterated in source order, so a straight-line chain propagates fully in one pass, and a chain long enough to need two requires a name to be used before it is assigned, which is not valid Python in that shape. The iteration is now a fixpoint anyway, because a fixed budget would be a depth limit dressed as data flow the first time a loop or a reordering appeared, but no defect is claimed and no repro row is filed. Claiming a defect whose reproduction does not exist would be the same error in the other direction.


**Method: the catalogue is now enforced on its own authors.** `tools/self_review.py` turns eight of the recorded defect classes into AST rules and runs them over `harness/` and `tools/` on every push. Justification for the shape: an exemption needs a written reason in `harness/self_review_allow.txt` or the loader refuses, because a suppression without a reason is the failure mode the corpus keeps documenting. Two rules are scoped deliberately, not for convenience: the ratio rule skips authoring scripts, which compute over their own lists rather than peer input, and the threshold rule reports only numbers whose names look like policy.

The first run found eleven high findings. Three were the intended fixtures, one was forgery detection reading a peer's claim in order to log it, and seven came from the ratio rule firing on report arithmetic. The scoping above resolved the seven; the four remaining are exempted with reasons rather than silenced. Three low findings stand unfixed and are the policy centralization the architecture still owes: `MAX_HOPS`, `MAX_WALL_SECONDS`, `MAX_FRAMES_PER_CONNECTION`.

**Method: mutation checks for the review's guards.** `tools/mutation_check.py` reverts each guard and confirms the test fails without it. Eight of nine guards are currently isolated by a test; the four that are not share fixtures where a second guard fires first, so a disabled guard leaves the suite green. The tool prints the shortfall rather than rounding it up, because a proof of coverage that skips the unproven cases is the same defect this repository keeps finding.

Changes to what the corpus contains, with the reason each decision was made. These are not defect fixes, so they carry no repro; the acquisition record with retrieval hashes is in [corpus/out/11-acquisition-batch-2.md](corpus/out/11-acquisition-batch-2.md).

- **Admitted D6 (Malpedia) as `unreviewed`, with zero claims.** Justification: family naming has to come from somewhere before any abuse-potential work is possible, while an index that cites primary reporting is a pointer, not evidence. Extracting claims from an index would manufacture a source of record it does not claim to be.
- **Admitted D7 (arXiv:2403.02546) at `manuscript_asserted`.** Justification: acceptance is asserted only in the arXiv comment field and no publisher record was opened, so a stronger tier would be an unverified claim. The three extracted claims are method and observation, each with a verbatim witness, and are barred from `security_rule` use.
- **Relaxed the metadata schema to permit non-arXiv sources.** Justification: `arxiv_id` was required and `source_url` was pattern-locked to arXiv, which was not a rule anyone chose, it was a side effect of the first batch. Left alone it would have silently restricted the corpus to one publisher. A companion check now fails if a document claims no arXiv id while pointing at arxiv.org.
- **Added `rejected_sources` and `check_rejected_sources`.** Justification: refusing a source is a claim about the world, so it needs the same treatment as any other claim. The check fails a refusal with no recorded attempt, an unknown reason code, or evidence under forty characters.
- **Rewrote three claim texts after the witness check rejected them.** Justification: `check_locator_witness` refuses a witness quote that restates the claim, and the first version of D7's claims copied the quote into the claim field. The guard caught its author doing the exact thing it exists to prevent, which is the only evidence that it works.

## Known gaps
, stated rather than implied

The three gaps in the previous revision are closed as defect classes, with what remains stated precisely rather than left as an excuse.

1. **ShareAlike prose (was R03's open half, now R21).** The `licence_scope` check catches the sentence shapes seen so far: a copyleft token and a scope-expansion phrase in one line, unaccompanied by a withdrawal. A rephrasing that avoids those tokens still passes. This is a pattern guard, not a legal reviewer.
2. **Invented locators (was an admitted blind spot, now R22).** A verified claim without a witness is blocked. A witness whose quote does not appear at the recorded offset in the source is not detected offline; `harness/retrievals/*.json` carries the `curl | sha256sum` command that lets any reader check it. Structural verification offline, content verification on re-fetch.
3. **Live protection (was recorded-only, now R23).** The live comparison exists and was executed against the real repository, passing. CI cannot run it: reading branch protection needs administration access and the default Actions token does not have it. So CI holds the recorded snapshot, and drift is caught by whoever runs `--live`, which is a person, not a schedule.
4. **Still unguarded, deliberately named.** No check verifies that a witness quote is semantically apt for the claim it supports. A real sentence from the right paper can support the wrong claim, and only review catches that.
